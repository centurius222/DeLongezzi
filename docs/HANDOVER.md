# DeLongezzi: handover

For whoever picks this project up, person or AI. Checked against the code on 2026-10-30 (release
v2.2.3). If this file and the code disagree, the code is right: fix this file.

## 1. What it is
- Espresso-machine firmware forked from [GaggiMate](https://github.com/jniebuhr/gaggimate)
  (Caffinnova S.r.l.), for one **ESP32-S3 N16R8** board (16 MB flash, 8 MB PSRAM).
- GaggiMate's two halves run in one firmware (`-DGAGGIMATE_MERGED`): the display half (logic, web
  server, plugins) and the controller half (sensors, heater, pump, safety). They talk through an
  in-memory loopback (`lib/NanoPbComm/src/ble/LoopbackPair.h`) instead of Bluetooth.
- No screen (`-DGAGGIMATE_HEADLESS`): the web page, served from flash, is the only interface.
- Hardware: wired like GaggiMate's "Pro Lego Build" (`GM_PRO_LEGO` in
  `lib/GaggiMateController/src/ControllerConfig.h`). Boiler probe PT1000 through a MAX31865
  (3-wire), pressure through an ADS1115, pump dimmer with zero-cross sensing (PSM), heater SSR,
  water-level touch pin, Bluetooth scales.
- Released: v2.2.3 (tag `v2.2.3`): the v2.2.2 program; the release file adds the 10 theme fonts.
  Commits on `main` after the tag: docs, the demo site, `.gitattributes`, the page files rebuilt
  with `gzip -n` (same content), and `storage/` with `scripts/build_release.sh` (the full release
  file from the repo).

## 3. How the parts talk
```
Browser (Preact app served from flash)
   │  WebSocket /ws: JSON {tp:"req:*"}           REST /api/*
   ▼
WebUIPlugin ──► Controller (modes, processes, settings, profiles)
                   │  Process: Brew / Manual / Grind / Steam / Pump
                   ▼
              GaggiMateClient ─ nanopb Frame ─► loopback (FreeRTOS queue)
                                                   ▼
                                           GaggiMateServer ─► GaggiMateController
                                                                ├ MAX31865 temperature, ADS1115 pressure
                                                                ├ heater SSR + PID, dimmed pump (PSM)
                                                                └ relays, buttons, safety
Back:  sensor frames ─► Controller callbacks ─► PluginManager events
       ─► WebUIPlugin sends evt:status every 500 ms ─► every /ws client ─► `machine` signal ─► pages
Scale: BLE (NimBLE) ─► BLEScalePlugin ─► Controller::onVolumetricMeasurement ─► stop by weight
```
- Storage: LittleFS holds shots `/h`, profiles `/p`, custom themes `/ct`, videos `/vid`, holiday
  files and fonts `/hol`, saved lists `/lists`, earlier runs' logs `/dlzlog`, the bean list
  `/beans.json` and the custom splash and logo pictures (`/splash.img`, `/logo.img`). NVS holds
  settings and Wi-Fi.
- Web state: the `machine` signal is fed by `evt:status`; the settings cache is dropped on
  `evt:changed`.

## 4. Build
Tools: PlatformIO with espressif32@6.12.0 (Arduino-ESP32 2.0.17 / ESP-IDF 4.4.7, precompiled, so
sdkconfig can't be changed), Node 20.19+ or 22.12+ (Vite 7), Python 3, bash and gzip (on Windows: WSL).
1. **Web page** (after any change in `web/`): `bash scripts/build_webui.sh`. It runs `npm ci` and
   the Vite build, gzips the files (`gzip -n`: no name or time, so a rerun without `web/` changes
   leaves the files as they are and a tag build keeps its version), and `embed_webui.py` writes
   `src/display/webassets/`.
2. **Firmware:** `pio run` (default env `delongezzi-single`). Output in
   `.pio/build/delongezzi-single/`: `firmware.bin`, `firmware.elf`, `bootloader.bin`, `partitions.bin`.
- Every library version is pinned in `platformio.ini`. A fresh clone builds the same code, with every
  symbol at the same address. The bytes still differ: the build time is built in (our
  `BUILD_TIMESTAMP`, "firmware built <time>", and HomeSpan's "Sketch Compiled" `__DATE__ __TIME__`),
  which shifts the merged text strings by a few bytes and every reference to them.
- The version comes from the git tag through `scripts/auto_firmware_version.py`: only `vX.Y.Z`
  is used, anything else (or no git) gives an empty version.

## 5. Flash
- Find the board: `ls /dev/serial/by-id/` shows `usb-Espressif_USB_JTAG_serial_debug_unit_<MAC>-if00`.
  Always pass that full path.
- **Update, keeping settings, Wi-Fi, shots, profiles, themes and videos:**
  `pio run -t upload --upload-port /dev/serial/by-id/<board>`. It writes the bootloader (0x0),
  partition table (0x8000), boot_app0 (0xe000) and program (0x10000), nothing else.
  Same with esptool: `esptool.py --chip esp32s3 --port <board> write_flash 0x10000 firmware.bin`.
- **Fresh install, wipes everything:**
  `esptool.py --chip esp32s3 --port <board> erase_flash && esptool.py --chip esp32s3 --port <board> write_flash 0x0 delongezzi-v2.2.3.bin`.
- Or from Chrome: https://centurius222.github.io/DeLongezzi/flasher/ (erase offered, then
  Wi-Fi over USB with Improv; our changes to the flasher are in section 7).

## 6. Flash layout and the release file
| Part | Start | Size | Holds |
|---|---|---|---|
| nvs | 0x9000 | 0x5000 | settings, Wi-Fi |
| app0 | 0x10000 | 4 MB | the program (no OTA: flashed by cable) |
| spiffs (LittleFS) | 0x410000 | 0xBE0000 | shots, profiles, themes, videos, fonts, logs and more (section 3) |
| coredump | 0xFF0000 | 64 KB | the last crash |

The release file `delongezzi-vX.Y.Z.bin` (16,711,680 bytes, written at 0x0) holds everything up to
the end of LittleFS. NVS is left blank, so it carries no Wi-Fi details or passwords.
`bash scripts/build_release.sh` makes it from the repo alone: `pio run`, then these two steps:
```sh
# data/ = storage/ (ct/<theme id>/, vid/<video id>/) + p/ (= data/p from the repo)
# + the 10 fonts from web/fonts in hol/fonts/, and a cache tag in every theme, video and font folder
mklittlefs -c data -b 4096 -p 256 -s 0xBE0000 storage_all.bin
esptool.py --chip esp32s3 merge_bin -o delongezzi-vX.Y.Z.bin --flash_mode dio --flash_freq 80m --flash_size 16MB \
  0x0 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin 0x410000 storage_all.bin
```
Cache tags: the board sends a folder's `tag` file as the ETag of its pictures, video or fonts (and
the page puts a video's tag in its link), and a browser keeps its copy until the tag changes. So
the script makes every tag from the folder's files (`"h-<16 hex>"`): a changed file always gets a
new tag. Uploads on the board write their own (`"<millis>-<size>"`).
The script also writes the theme backup `delongezzi-themes-vX.Y.Z.json` from `storage/ct` (the
format of Settings › Custom Themes › Restore themes, themes in name order, no videos); it goes on
the release next to the .bin. Until v2.2.3 it was a second copy in git (`themes/`, now removed;
the README links the copy at tag v2.2.3 until v2.2.4 is out).
The tools come with PlatformIO: `mklittlefs` is `~/.platformio/packages/tool-mklittlefs/mklittlefs`
(PlatformIO installs it only for `pio run -t buildfs`; the script runs that when it's missing),
`esptool.py` is `python3 ~/.platformio/packages/tool-esptoolpy/esptool.py`, and `boot_app0.bin` is in
`~/.platformio/packages/framework-arduinoespressif32/tools/partitions/`. `storage/` was taken out of
the v2.2.3 release file. To take a release file's storage out again (to check it, or to start from
it; leave out its `tag` files, the script makes them), unpack it (works for images mklittlefs made):
```sh
dd if=delongezzi-v2.2.3.bin of=storage.bin bs=4096 skip=$((0x410000/4096)) count=$((0xBE0000/4096))
mklittlefs -u data -b 4096 -p 256 -s 0xBE0000 storage.bin
```
Tested 2026-10-30: a fresh clone at `v2.2.3` built with these steps gives a file with the same
bootloader, partition table and boot_app0 byte for byte, the same code (every symbol at the same
address) and the same 217 storage files as the published v2.2.3; it was flashed to a board and
answered as DeLongezzi v2.2.3.

Tested 2026-10-30 with `storage/` in the repo: `bash scripts/build_release.sh` at tag `v2.2.3`
(with `storage/` and the script copied in) gives the same bootloader, partition table and
boot_app0 byte for byte, the same 217 storage files, and a program with all 17,812 symbols at the
same address that differs in 79 bytes only: the two build times inside it and the checksums over
them. In a fresh clone of `main` the script runs from start to end too.

Reproducible since 2026-10-30: the build time inside the program is the commit's time
(`SOURCE_DATE_EPOCH`, which the compiler also uses for `__DATE__`/`__TIME__`), and the build
folder and PlatformIO's packages folder get fixed names in the debug info, so the same commit
gives the same program byte for byte (tested on one PC: two fresh clones in different folders, and
a plain `pio run` against the script). The storage image does not: mklittlefs stores each folder's
change time, which no program can set, so about 25 bytes differ per build while the files inside
are the same. The published SHA-256 checks the download; to check a rebuild, compare the program
part and unpack the storage (above).
- Only a clean build is reproducible: parts compiled earlier keep their old build times
  (`scripts/build_release.sh` always builds from clean).
- The permanent log's "firmware built …" line shows the commit's time, not when it was built.
  With uncommitted changes (or without git) it's the real time.
- The debug info names the repo `.` and PlatformIO's packages `/platformio/packages`. gdb and
  `analyze_coredump.py` still find functions and lines; to open framework sources in gdb:
  `set substitute-path /platformio/packages /home/<you>/.platformio/packages`.

## 8. Traps and what they cost
| Trap | Cost if missed | Do this |
|---|---|---|
| A full chip erase (`pio run -t erase`, or `scripts/flash.sh` until 2026-10-30) before uploading the program | settings, Wi-Fi, shots, profiles, themes, videos and fonts gone, and nothing puts them back | update with the program-only flash in section 5 (`scripts/flash.sh` does that now); for a full install write the release file |
| Build and flash chained with `;` | once a failed build was followed by an erase: a board with no program | chain with `&&` |
| Two ESP32-S3 boards on USB (a DIY scale, a spare) show the same name, and `/dev/ttyACM0`/`1` swap between plug-ins | flashing the wrong board wipes it | always the full `/dev/serial/by-id/...` path; never let pio pick the port |
| Flashing while a shot runs | the shot dies; outputs are not held while no program runs | check `evt:status` `process.a` is 0 for about 6 s (`/api/status` doesn't show it) |
| Opening the USB serial port | restarts the board | not while brewing |
| Running on a PC's USB power alone | flash and LittleFS reads stall 30–100 s, the watchdog freezes it, it looks like a firmware bug | test on the machine's own power supply |
| A tag or version that isn't `vX.Y.Z` | the built-in GitHub update code parses it at every boot: crash loop, USB port locked (hold BOOT while plugging in to flash again) | tag only `vX.Y.Z`; `auto_firmware_version.py` enforces it |
| A `web/` change without `scripts/build_webui.sh` | the machine keeps serving the old page | always run it before `pio run` |
| Editing `web_ui.bin` by hand, or `web_ui_blob.S` | a stale compiled blob was linked once: blank page | only `embed_webui.py` writes them; it puts the blob's sha256 in `web_ui_blob.S` so the blob is always rebuilt |
| Tailwind 4 scans every file under `web/` that git doesn't ignore | build output or new folders add CSS to the machine's page | keep outputs in `web/.gitignore` (`dist`, `dist-demo`) and the `@source not` lines in `web/src/style.css`; check a normal build gives the same asset names |
| Turning USB logging back on | a log write to an unread USB port blocked the web server task for up to a minute; Improv uses the same port | keep `esp_log_level_set("*", ESP_LOG_NONE)` (`main.cpp`); read `/api/log` instead |
| `PSRAM_MALLOC_THRESHOLD` below 256 | LittleFS read buffers land in PSRAM: slow storage, watchdog trips | keep 256 (`src/display/util/PsramThreshold.h`) |
| Heat-up check (on by default): at ≥90 % heater output, mains present, more than 15 °C below target and no flow, a rise under 5 °C in 60 s stops the heater | error 4, latched until a restart; on a bench without a heater it trips every time | a real trip means no heat reaches the probe: heater power, thermal fuse or thermostat, SSR, or the probe off the boiler. The switch is in Settings › Machine (bench only) |
| Bench without sensors | ADS1115 and PCA9634 errors at boot | expected |
| Improv over USB (the web flasher's Wi-Fi step) | before v2.2.2: the reply waited in the USB send buffer (step skipped), and an unset library callback crashed the board on a wrong password | keep `sendUsbNow()` in `ImprovPlugin.cpp` and the `nullptr` callbacks in `lib/ImprovWiFi` |
| ESP Web Tools asks for Wi-Fi only if Improv answers within 30 s and erase was ticked | users never get the Wi-Fi step | keep the manifest settings; the firmware must answer Improv soon after boot |
| Holding BOOT while installing (GPIO0 is latched until power-off) | the USB restart leaves the board in flash mode, so no Wi-Fi step | fixed in the site's ESP Web Tools (section 7); after an esptool flash with BOOT, unplug and replug |
| `delongezzi.local` (mDNS) doesn't resolve on many PCs | a dead link after setup | Improv reports `http://<IP>/` |
| `mklittlefs` can make images the firmware mounts but can't unpack the machine's own LittleFS | hours lost on flash dumps | read a machine's files through the web API |
| LittleFS is formatted only if the partition's first 8 KB are all 0xFF | none: any other mount error keeps the data | erase the partition to start empty |
| GitHub Pages types a file by its ending | the demo's extensionless videos came as `application/octet-stream`, and the page plays a video only when the type says `video/` | the demo keeps `video.mp4`, `video.webp`, `still.webp` and maps the page's addresses to them |
| The demo under `/<repo>/demo/` instead of a site root | every `/assets`, `/api` and page address breaks | its own `<user>.github.io` repo |
| `/api/settings` and full flash backups contain the Wi-Fi and Home Assistant passwords | leaked credentials | never print, log, commit or publish them |
| A crash dump needs that build's exact `firmware.elf` | an undecodable dump | keep the `.elf` of every build you flash; PlatformIO's gdb needs libpython2.7 (else use esp-coredump and addr2line) |
| An unknown page address | blank page (a stray `{' '}` inside `<Router>` in `web/src/index.jsx`), also on the machine | known bug, still in v2.2.3 |
| A machine flashed with v2.2.2 or older has no theme fonts | a theme set to one of them shows the default font | reflash v2.2.3 or later, or `python3 scripts/upload_fonts.py <machine address>` |
| Hotspot password `delongezzi` is public, and the web page has no login | anyone nearby, or on the network, can run the machine | change the hotspot password; never forward a port to it |

## 9. Rules the code depends on
- **Boot order** (`main.cpp setup()`): `dlzlog_boot()`, then `gpio_install_isr_service()` (installing
  it later overflowed ESP-IDF's 1 KB ipc1 task: 0 crashes in 20 restarts after the move), then
  `gmController.outputsOff()` (relays off before anything else), then the PSRAM threshold.
- **Watchdog:** 15 s with panic off (`esp_task_wdt_init(15, false)`): a long flash operation heals
  instead of rebooting.
- **Tasks** (core pinning is deliberate; async_tcp must stay on core 0):

  | Task | Core | Priority | Stack |
  |---|---|---|---|
  | loopTask (Arduino) | 1 | 1 | 6144 |
  | Controller::loopLogic | 1 | 3 | min × 6 |
  | GaggiMateController | 1 | 2 | 4096 |
  | async_tcp | 0 | 10 | 6144 |
  | WebBackground (theme and video lists, storage walk, picture cache) | 0 | 1 | 5120 |
  | ShotHistoryPlugin::loop | 0 | 1 | min × 6 |
  | BLEScaleTask | 1 | 1 | 4608 |
  | Settings::loop | any | 1 | 3072 |

  Not in the table: the controller's sensor and pump tasks (`ADSAdc::loop`, `DimmedPump::loop`,
  `DigitalInput::loop` and others: priority 1, any core, min × 4) and two one-shot tasks
  (`settingsRestart`, the history rebuild).
- **Web limits:** at most 6 WebSocket clients (`DEFAULT_MAX_WS_CLIENTS`); `OPEN_LIMIT` 4 open
  requests, then `503` with `Retry-After: 1`; `HEAVY_LANES` 2 big responses; `HEAVY_STUCK_MS` 5000.
- **Storage walk** (`LittleFS.usedBytes()`, about 5 s): at start, when asked, and every 15 min in
  standby, only on WebBackground.
- **Updates over Wi-Fi stay off:** `req:ota-start` is blocked and the periodic check is commented
  out. No blocking TLS on loopTask.
- **Concurrency:** lock order `ws.clientsLock()` → `wsStatsMutex`; `rxBuffers` only under
  `rxMutex`. A Process is read only under `controller->getProcessLock()`, released before any
  WebSocket send (GM-147). Close clients only with `requestClose()`. On a Wi-Fi drop the server
  keeps running; only `ws.cleanupClients()`.
- **Safety:** ping every 2 s (`PING_INTERVAL`); after 20 s without one (`PING_TIMEOUT_SECONDS`)
  the controller turns heater, pump and valves off. Thermal runaway, sensor fault and the heat-up
  check give error 4, latched until a restart. `MAX_SAFE_TEMP` is 170 °C.
- **Error codes** (`lib/NanoPbComm/src/GaggiMateComm.h`): 0 none, 1 send, 2 receive, 3 protocol,
  4 runaway (heater stopped for safety), 5 timeout (not latched), 6 autotune timeout (PID kept).
- **Formats:** `PROTOCOL_VERSION` 3 (`lib/NanoPbComm/src/Protocol.h`); `SHOT_LOG_VERSION` 5 and
  `SHOT_INDEX_VERSION` 1, layouts byte-exact. Modes: 0 standby, 1 brew, 2 steam, 3 water,
  4 grind, 5 manual.

## 10. Protocol reference
**`evt:status`**, every 500 ms to each open `/ws` client. The web app reads these keys, so renaming
one breaks it: `tp ct tt pr fl pt m sw wk nw mp mw wm p puid cp cd gp tw bta bt btd led gtd gtv gt
gact wl tof rssi lat pw hp err bw cw bc`. `process` (`a s l e tt pt pp`, plus top-level `pkr pf tf`)
appears when there is a current or last process:
- brew: `s` is `brew` or `infusion`, `l` the phase name or `Finished`;
- manual: `s:"manual"`, `pf` is the scale's flow when a scale is connected;
- grind: `s:"grind"`;
- steam and water: only `a`.

**WebSocket commands** (JSON with `tp`; answers are `res:*` with the same `rid`):
| Send | Result |
|---|---|
| `req:process:activate` / `req:process:deactivate` | start / stop; after a stop in manual mode the finished shot stays on screen |
| `req:change-mode` `{mode}` | stop, clear, set the mode |
| `req:tare` | refused while a shot runs; otherwise tares the scale and clears the finished shot |
| `req:manual-pressure` `{pressure}` | applied live during a manual shot |
| `req:manual-weight` `{weight}` | read when the process starts (0 = off) |
| `req:theme` `{holidayMode, keepTheme}` | saved; every page gets `evt:changed` |
| `req:history:rebuild` | answers "Rebuild started" at once, then `evt:history-rebuild-progress` |
| `req:ota-start` | blocked |
| unknown `tp` or bad JSON | ignored |

**HTTP:**
| Request | Result |
|---|---|
| `GET /` and page addresses | the embedded gzip page |
| `GET /api/status` | mode and temperatures only (no `process`: use the WebSocket for "shot running") |
| `GET /api/settings` | all settings, **including passwords** |
| `GET /api/log`, `/api/log?prev=1..3` | permanent log of this run and the three before |
| `GET /api/core-dump` | the last crash dump |
| tagged picture with a matching `If-None-Match` | `304` |
| `/generate_204`, `/hotspot-detect.html`, `/ncsi.txt`, `/canonical.html`, `/redirect` | captive-portal redirect to `http://4.4.4.1/` |
| `/connecttest.txt` (Windows 11 workaround), `/success.txt` (Firefox) | redirect to `http://logout.net` / `200` |

## 11. Debugging
- The USB console is silent on purpose (Improv uses it). Use `/api/log` (and `?prev=1..3`) and
  Settings › Diagnostics.
- A boot line shows the reset reason, `prevRun` and the stored coredump size; `firmware built
  <time>` tells which build is running.
- Crash: download `/api/core-dump`, then `python3 scripts/analyze_coredump.py <dump> <firmware.elf>`
  with the exact `.elf` of that build.
